Nginx2root Fix(Upgrade)

发表于 2026-11-19
本文字数： 6.1k 阅读时长 ≈ 10 分钟

What is NGINX2Root?

nginx2root is a collection of five distinct nginx vulnerabilities and one Linux kernel vulnerability. Each has a proven exploit. The most severe enables unauthenticated remote code execution; chained with a separate Linux kernel vulnerability, it can lead to host root.

Fixed version: 1.31.9

Five nginx findings and one kernel vulnerability
The most severe of the five allows unauthenticated remote code execution on web servers running a common nginx configuration. This remote code execution can be chained with a separate Linux kernel vulnerability to reach host root, remotely and without authentication.

Who is affected?

The version range below applies to the HTTP/2 remote-code-execution finding, the most severe of the five. Official nginx releases from 1.9.5 through 1.31.8 contain the affected code. Exposure requires HTTP/2 support in the nginx build and an affected listener that accepts HTTP/2 connections.

Each of the other four CVEs is a distinct vulnerability with its own affected range and exploit. Check its individual advisory rather than applying the HTTP/2 finding’s version range to all five.

Distribution packages, appliances, and container images may backport a security fix while retaining an older version string. Confirm patch status from the relevant vendor advisory instead of relying on nginx -v⁠ alone. The host-root stage uses a separate Linux SCTP kernel vulnerability and must be assessed separately.

How do I fix it?

Apply the fixed nginx release or your vendor’s security update as soon as it is available. If you cannot update immediately, disable HTTP/2 on every affected nginx listener until the fix is applied. This mitigates the HTTP/2 finding. For the other CVEs and the Linux kernel finding, see the response guide in our blog post.
